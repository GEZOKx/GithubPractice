1. addEventListener

Es la forma correcta de "escuchar" un evento sobre un elemento. Recibe el tipo de evento (como texto) y una función que se ejecuta cuando ese evento ocurre.

const boton = document.querySelector("#miBoton");

boton.addEventListener("click", function () {
  console.log("¡Me dieron clic!");
});

// también funciona con arrow function
boton.addEventListener("click", () => console.log("¡Clic otra vez!"));
A diferencia de otras formas de poner un evento (ver siguiente sección), addEventListener permite agregar varios listeners del mismo tipo al mismo elemento — ninguno sobrescribe al otro.

Lista completa de eventos disponibles: MDN — Events.

2. Formas viejas de poner un evento EXTRA

Antes de addEventListener existían otras dos formas. Conviene reconocerlas (van a aparecer en código viejo) pero no usarlas en código nuevo.

Evento inline, escrito directo en el HTML — mezcla HTML con lógica de JS, difícil de mantener:

<button onclick="console.log('clic')">Botón</button>

Propiedad onclick del elemento — ya es JS puro, pero solo permite un handler por evento: el segundo que asignen sobrescribe al primero.

boton.onclick = function () {
  console.log("Primero");
};

boton.onclick = function () {
  console.log("Segundo"); // esta es la única que queda
};

3. this dentro del callback

Cuando el callback es una función normal (no arrow), this dentro de ella apunta al elemento que disparó el evento — es un caso más de la regla que ya vieron: this depende de quién llama a la función, y aquí quien la "llama" es el elemento.

function alAgrandar() {
  this.classList.toggle("grande");
}

document.querySelector(".caja").addEventListener("click", alAgrandar);
Si el callback es una arrow function, this NO apunta al elemento — toma el this del lugar donde se escribió la arrow function (como ya vieron antes). Por eso, cuando se necesita this como el elemento, el callback debe ser una función normal.

4. El objeto evento

El callback siempre recibe un argumento — el objeto evento — con información sobre lo que pasó. Es común nombrarlo e o evt.

boton.addEventListener("click", function (e) {
  console.log(e); // el objeto completo, para explorar en consola
});
PropiedadQué da
e.targetEl elemento exacto donde ocurrió el evento
e.currentTargetEl elemento que TIENE el listener (puede ser distinto de target — ver delegación)

5. Eventos de teclado

keydown (se presiona) y keyup (se suelta) dan información de la tecla en el objeto evento:

const input = document.querySelector("#texto");

input.addEventListener("keydown", function (e) {
  console.log("Se presionó:", e.key);  // ej. "a", "Enter", "Shift"
  console.log("Código:", e.code);      // ej. "KeyA", "Enter", "ShiftLeft"
});

Para detectar teclas sin importar qué elemento tenga el foco, se escucha sobre window en vez de un elemento específico:

window.addEventListener("keydown", function (e) {
  if (e.code === "ArrowUp") console.log("¡Arriba!");
});

6. removeEventListener y once

Para quitar un listener, se necesita la misma función que se usó al agregarlo — por eso una arrow function anónima no se puede quitar después, hay que guardarla en una variable.

function saludar() {
  console.log("Hola");
}

boton.addEventListener("click", saludar);
boton.removeEventListener("click", saludar); // ya no hace nada al dar clic

Cuando se sabe de antemano que el listener solo debe dispararse una vez, es más simple usar la opción { once: true } — se quita solo después de la primera vez:

boton.addEventListener("click", saludar, { once: true });

7. Formularios y preventDefault

El evento submit se dispara al enviar un formulario — y por default, el navegador recarga o cambia de página. e.preventDefault() cancela ese comportamiento, para manejar el envío con JS en su lugar.

const form = document.querySelector("#miForm");

form.addEventListener("submit", function (e) {
  e.preventDefault();
  console.log("Formulario interceptado, no hubo recarga");
});

Los campos del formulario se pueden leer por su atributo name, a través de form.elements:

<input type="text" name="usuario" />
const usuario = form.elements.usuario;
console.log(usuario.value);

8. input vs change

EventoSe dispara...
inputCada vez que el valor cambia, mientras se escribe
changeSolo cuando el elemento pierde el foco, después de haber cambiado
 
const campo = document.querySelector("#texto");
const vista = document.querySelector("#vistaPrevia");

campo.addEventListener("input", function () {
  vista.textContent = campo.value; // se actualiza letra por letra
});

9. Event bubbling (propagación)

Cuando ocurre un evento dentro de un elemento anidado, el evento "burbujea" hacia arriba: se dispara también en cada elemento padre, hasta llegar a document.

<div id="contenedor">
  <button id="interno">Clic aquí</button>
</div>
document.querySelector("#interno").addEventListener("click", () => {
  console.log("Clic en el botón");
});

document.querySelector("#contenedor").addEventListener("click", () => {
  console.log("Clic en el contenedor"); // también se dispara
});

Para evitar que un evento siga burbujeando hacia los padres, se usa e.stopPropagation() dentro del callback.

10. Delegación de eventos

En vez de poner un listener en cada elemento de una lista (que puede crecer dinámicamente), se pone un solo listener en el contenedor, y se usa e.target para saber en cuál elemento hijo se hizo clic. Aprovecha el bubbling de la sección anterior.

const lista = document.querySelector("#lista");

lista.addEventListener("click", function (e) {
  console.log("Se hizo clic en:", e.target);
  e.target.classList.toggle("seleccionado");
});
Esto funciona incluso con elementos que todavía no existen cuando se agregó el listener — si después se agrega un nuevo <li> a la lista, ya queda cubierto, sin tener que agregarle su propio listener.

11. Patrón Observer

addEventListener es, por dentro, una implementación del patrón Observer: un objeto (el "sujeto") mantiene una lista de funciones interesadas ("observadores"), y cuando algo pasa, les avisa a todas llamándolas una por una.

Se puede construir la misma idea a mano, sin que tenga nada que ver con el DOM — sirve para que cualquier objeto propio "avise" cuando algo le pasa:

class Emisor {
  constructor() {
    this.listeners = [];
  }

  addEventListener(callback) {
    this.listeners.push(callback);
  }

  emitir(dato) {
    this.listeners.forEach((callback) => callback(dato));
  }
}

const carrito = new Emisor();

carrito.addEventListener((total) => console.log(`Nuevo total: $${total}`));
carrito.addEventListener((total) => console.log(`Actualizando UI con $${total}`));

carrito.emitir(150); // dispara ambos listeners, en el orden en que se agregaron
Visto así, document.querySelector(...).addEventListener(...) deja de ser "magia especial de los botones" — es el mismo patrón que cualquiera puede escribir en una clase propia.

EXTRA Esta versión mínima no tiene removeListener ni tipos de evento (solo un tipo de aviso) — una versión más completa guardaría los callbacks agrupados por tipo de evento, igual que hace el DOM real.
