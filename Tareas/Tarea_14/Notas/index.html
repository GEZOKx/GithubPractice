3. Revisando response.ok (el error "silencioso")

        
Pedimos un usuario que no existe (404) y mostramos que fetch NO lanza error solo.

        
        

        
response.ok: propiedad booleana del Response. Es true si el status es 2xx (200 a 299) y false si es 404, 500, etc. fetch NO rechaza con un 404 (el servidor sí contestó), por eso se revisa a mano. if (!response.ok) se lee “si la respuesta NO fue exitosa” (! es el NO lógico).

      



      

        
4. Lanzando un Error a mano cuando !response.ok

5. JSON anidado

        
Cada usuario trae address.geo.lat (tres niveles) y company.name (dos niveles).

        
        

        
address.geo.lat: se lee de izquierda a derecha, un punto por nivel: usuario → address (objeto) → geo (objeto) → lat (el valor). Es lo mismo que usuario["address"]["geo"]["lat"]. Si algún nivel no existe (undefined), el siguiente punto lanza error.
